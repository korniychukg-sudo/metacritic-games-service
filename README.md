# Metacritic Games Digest

Сервис раз в час заходит на Metacritic в раздел Games, берёт 20 новых игр, которые сегодня ещё не обрабатывал,
и сохраняет их в свою базу. Если игра уже есть в базе, сервис её обновляет. Для каждой игры он делает
отдельные резюме отзывов критиков и отзывов игроков: что нравится и что нет. Ещё он находит самый популярный
летсплей на YouTube, переводит речь блогера в текст и пишет по этому тексту заключение. Всё это видно
в веб-интерфейсе, там же есть мониторинг работы сервиса в реальном времени.

Тестовое задание на позицию AI Automation Engineer. Сервис работает без единого секрета: LLM по умолчанию
вызывается через бесплатный анонимный эндпоинт.

## Возможности

| Требование задания | Как сделано |
|---|---|
| Раз в час 20 новых игр | Фоновый планировщик (`app/scheduler.py`) запускает обработку каждые `RUN_INTERVAL_MINUTES` (60) минут. Если база пустая, первый запуск идёт через 15 секунд после старта. После перезапуска интервал отсчитывается от прошлого запуска, он хранится в БД. |
| Первый проход дня: New Releases | Первые 20 игр берутся из блока New Releases на `/game/`. Источник: тот же JSON, из которого Metacritic рендерит этот блок (`finder ... new-releases-carousel`, порядок совпадает 1:1). |
| Следующие проходы: SEE ALL, сортировка «новые» | Страницы `/browse/game/all/all/all-time/new/` (JSON `finder ... sortBy=-releaseDate`, 24 игры на страницу). Курсор страницы хранится по дням (`day_state`). Страница считается пройденной, только когда обработаны все игры на ней. Если страница не поместилась в пачку, следующий запуск продолжит с неё же. |
| Сегодня не обрабатывал / новый день заново | Таблица `processed(day, game_id)` хранит, что обработано за день. Новый день начинается с New Releases, курсор стоит в начале. Границы дня считаются по `DAY_TZ` (по умолчанию Москва). |
| Добавить или обновить | Upsert по id тайтла Metacritic. Платформы перезаписываются, у игры растёт счётчик `times_processed`. |
| Название, обложка, разработчик, описание, видео | Всё берётся из одного запроса composer: `product` (обложка `cardImage`, разработчики из `production.companies`, видео JW Player `embedUrl` и HLS `manifestUrl`). |
| Платформы + Metascore + Userscore | Metascore по каждой платформе берётся из `product.platforms[]`. Userscore ведущей платформы приходит в composer, по остальным платформам сервис делает отдельный запрос. Ноль без оценок хранится как «нет оценки». |
| Резюме отзывов отдельно для критиков и игроков | Выборка 7/7/7 (positive / mixed / negative) из composer. Если негативных отзывов в выборке мало, сервис догружает негативные. Дальше LLM, ответ строго в JSON `likes/dislikes/verdict`. При повторных обходах резюме пересчитывается, только если изменился набор отзывов (хэш). |
| Веб: список, карточка, фильтр по платформам, поиск, сортировка по рейтингу | Серверный рендеринг на Jinja2. Фильтр по платформе меняет и сами оценки: показываются и сортируются оценки выбранной платформы. Сортировка по Metascore и Userscore в обе стороны, а также по дате и названию. Поиск по подстроке названия без учёта регистра. |
| Похожие игры | Считаются по уже загруженным играм: TF-IDF по описанию с косинусной близостью, плюс совпадения франшизы, разработчика, жанров и платформ (взвешенная сумма). Пересчитываются после каждого запуска. В карточке показываются 5 похожих игр с причиной, по клику открывается их карточка. |
| Доп. 1: летсплей | YouTube-поиск без API-ключа: сортировка Popularity, ролики длиннее 20 минут, два запроса (`let's play` и `прохождение`). Сервис отсекает трейлеры и обзоры, проверяет, что название игры есть в названии ролика, предпочитает let's play / walkthrough / прохождение и из оставшихся берёт ролик с максимумом просмотров. Речь блогера переводится в текст через субтитры YouTube (ручные или автоматические, ASR), библиотека `youtube-transcript-api`. По расшифровке LLM пишет заключение: summary, плюсы, минусы, вердикт. Ссылка на ролик и фрагменты расшифровки сохраняются в карточке. |
| Доп. 2: мониторинг и кнопка | Страница `/monitor` получает обновления по Server-Sent Events (`/api/events`). На ней видны статусы воркеров (планировщик, обработчик, Metacritic, YouTube, LLM), прогресс текущего запуска (игра и шаг), счётчики за день и всего, ошибки, история запусков и живой журнал. Кнопка «Запустить обработку сейчас» защищена от параллельных запусков: lock, ответ 409. |

## Архитектура

```
             ┌────────────── FastAPI (app/main.py) ───────────────┐
 браузер ──▶ │  /  /game/{slug}  /monitor   Jinja2 + немного JS   │
             │  /api/games  /api/status  /api/events (SSE)        │
             │  POST /api/run · POST /run · /healthz              │
             └──────┬──────────────────────────────┬──────────────┘
                    │ читает                       │ start_background()
              ┌─────▼─────┐   пишет   ┌────────────▼─────────────┐  каждый час
              │  SQLite   │◀──────────│ Pipeline (app/pipeline)  │◀─ Scheduler
              │ DB_PATH   │           │  select_batch → игра →   │
              └───────────┘           │  резюме → летсплей →     │──▶ Monitor
                                      │  похожие игры            │   (статусы, лог)
                                      └──┬─────────┬─────────┬───┘
                     PoliteClient ≤1 rps │         │         │ последовательно, пауза
                       ┌─────────────────▼┐ ┌──────▼──────┐ ┌▼──────────────────┐
                       │ backend.metacritic│ │  YouTube    │ │ OpenAI-совместимый│
                       │ finder / composer │ │ search/watch│ │ chat API (LLM)    │
                       │ reviews stats     │ │ + субтитры  │ │ + запасной режим  │
                       └───────────────────┘ └─────────────┘ └───────────────────┘
```

Модули:

- `app/metacritic.py`: клиент и парсеры JSON-бэкенда Metacritic (finder, composer, reviews, stats).
- `app/selection.py`: чистая логика выбора пачки (New Releases, затем SEE ALL), покрыта тестами.
- `app/youtube.py`: разбор выдачи (`ytInitialData`), выбор летсплея, страница ролика, расшифровка.
- `app/llm.py`: клиент OpenAI-совместимого API. Вызовы идут последовательно с паузой, есть ретраи и
  извлечение JSON из ответа с ```` ``` ````-обёрткой. Если сервер отклоняет запрос (402/413), бюджет промпта
  уменьшается.
- `app/summarize.py`: промпты, валидация ответов, экстрактивные резюме для запасного режима.
- `app/similarity.py`: похожие игры (TF-IDF + метаданные) без внешних библиотек.
- `app/pipeline.py`: один запуск. Ошибка в одной игре не останавливает запуск.
- `app/scheduler.py`: фоновый поток с часовым интервалом.
- `app/monitor.py`: состояние воркеров, счётчики, кольцевой буфер логов для SSE.
- `app/db.py`: схема SQLite (WAL) и запросы.

Как сервис обращается с внешними сервисами:

- Браузерный User-Agent.
- Не больше одного запроса в 1,1 с на каждый хост.
- Таймауты 30 с.
- 3 ретрая с экспоненциальной паузой на 429/5xx и сетевые ошибки. 404 не ретраится.

На одну игру обычно уходит 2–5 запросов к Metacritic и 3–5 к YouTube.

### Запасные режимы (карточка никогда не пустая)

- **LLM не ответила.** Вместо её резюме строится экстрактивное: ключевые фразы из положительных
  и отрицательных отзывов. В карточке оно помечено как «цитаты без LLM». В конце каждого запуска сервис
  пробует пересчитать через LLM до `LLM_BACKFILL_LIMIT` таких резюме. Карточки сами «дозревают», когда LLM
  снова доступна.
- **Нет расшифровки у самого популярного ролика.** Сервис берёт следующий кандидат, до 3 штук. Если
  расшифровки нет ни у одного, заключение строится по названию и описанию ролика
  (`llm-description` / `description`). Если нет и описания, сохраняется только ссылка с пометкой о причине.
- **Метод в данных.** В каждом резюме записано, каким способом оно получено: `method`
  (`llm`, `extractive`, `llm-transcript`, `extractive-transcript`, `llm-description`, `description`, `none`).
  В интерфейсе метод показан бейджем.

## Запуск локально

Нужен Python 3.11+.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.asgi:app --port 8000
```

Откройте http://127.0.0.1:8000. При пустой базе первая обработка стартует сама примерно через 15 секунд.
Её ход видно на http://127.0.0.1:8000/monitor. Для быстрой проверки можно уменьшить пачку:
`BATCH_SIZE=4 .venv/bin/uvicorn app.asgi:app`. Также можно запустить обработку вручную:
`curl -X POST 'localhost:8000/api/run?limit=3'`.

Тесты работают офлайн, на сохранённых ответах из `docs/samples/`:

```bash
.venv/bin/python -m pytest
```

Docker:

```bash
docker build -t mc-digest .
docker run -p 8000:8000 -v mc-data:/data mc-digest
```

### Деплой (Railway)

В репозитории есть `Dockerfile`, `Procfile` и `railway.json`: сборка из Dockerfile, healthcheck `/healthz`,
одна реплика. Сервис слушает `PORT`. Подключите Volume и укажите `DB_PATH=/data/games.db`, иначе база
пропадёт при пересборке. Секреты не нужны.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8000` | порт HTTP (Docker/Procfile) |
| `DB_PATH` | `./data/games.db` | файл SQLite (на хостинге путь на volume) |
| `BATCH_SIZE` | `20` | игр за один запуск |
| `RUN_INTERVAL_MINUTES` | `60` | интервал планировщика |
| `SCHEDULER_ENABLED` | `1` | `0` выключает автозапуск, ручная кнопка при этом работает |
| `STARTUP_DELAY_SECONDS` | `15` | задержка первого запуска при пустой базе |
| `DAY_TZ` | `Europe/Moscow` | часовой пояс, по которому считается «сегодня» |
| `BROWSE_PAGE_SIZE` / `BROWSE_MAX_PAGES` | `24` / `4` | размер страницы SEE ALL и предел страниц за запуск |
| `LLM_BASE_URL` | `https://text.pollinations.ai/openai` | любой OpenAI-совместимый API (к адресу добавляется `/chat/completions`) |
| `LLM_API_KEY` | пусто | ключ. Без ключа заголовок `Authorization` не отправляется |
| `LLM_MODEL` | `openai` | модель |
| `LLM_MAX_PROMPT_CHARS` | авто | бюджет промпта в символах: 6000 для анонимного Pollinations, 9000 для остальных. Если сервер дважды подряд отвечает 402/413, бюджет уменьшается |
| `LLM_MIN_GAP_SECONDS` | авто | минимальный интервал между началами вызовов LLM: 32 с для анонимного Pollinations, 3 с для остальных |
| `LLM_BACKFILL_LIMIT` | `4` | сколько резюме из запасного режима пересчитывать через LLM за запуск |
| `LLM_ENABLED` | `1` | `0` отключает LLM, остаются только экстрактивные резюме |
| `YOUTUBE_ENABLED` | `1` | поиск летсплеев |
| `YOUTUBE_PROXY_URL` | пусто | HTTP(S)-прокси для расшифровок (нужен на облачных IP, см. ниже) |
| `LETSPLAY_REFRESH_DAYS` | `7` | как часто перепроверять уже найденный летсплей |
| `HTTP_MIN_INTERVAL` | `1.1` | минимальная пауза между запросами к одному хосту, с |

## API

- `GET /api/games?q=&platform=&sort=&page=`: список.
  `sort` ∈ `date_desc|date_asc|metascore_desc|metascore_asc|userscore_desc|userscore_asc|title|updated`.
- `GET /api/games/{slug}`: полная карточка, включая похожие игры.
- `GET /api/platforms`: платформы с количеством игр.
- `GET /api/status`: состояние воркеров, счётчики, история запусков, последние ошибки.
- `GET /api/events`: поток SSE (`event: status`, `event: log`).
- `POST /api/run[?limit=N]`: запустить обработку. Отвечает 202, или 409, если обработка уже идёт.
- `GET /healthz`: healthcheck.

## Известные ограничения

- **Бесплатная LLM.** Анонимный Pollinations (`model=openai`, на деле `gpt-oss-20b`) пропускает примерно один
  запрос в 30 секунд с одного IP. Если запросы идут чаще, он отвечает `402` с пустым телом (замерено 14.10.2026).
  Поэтому вызовы идут строго по очереди, с интервалом 32 с между началами. На игру уходит до трёх вызовов:
  критики, игроки, летсплей. Резюме по отзывам игроков без отзывов не запрашивается. Полная пачка из 20 игр
  обрабатывается примерно за 30–40 минут и укладывается в часовой интервал. Если LLM всё же отказала,
  карточка получает экстрактивное резюме, а на следующих запусках его пересчитывает этап досчёта.
  С собственным ключом любого OpenAI-совместимого провайдера (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`)
  интервал 3 с и пачка проходит за несколько минут. Модель иногда отвечает по-английски на английские
  отзывы. Такой ответ отбрасывается валидатором и запрашивается повторно.
- **Расшифровки YouTube с облачных IP.** С облачных IP (Railway, AWS, GCP) YouTube обычно блокирует
  получение субтитров (`RequestBlocked`). Тогда сервис переходит к заключению по описанию ролика. Чтобы
  получать полноценные расшифровки на хостинге, нужен `YOUTUBE_PROXY_URL` (резидентный прокси). Локально
  всё работает.
- **Расшифровка = субтитры YouTube.** «Перевод речи в текст» выполняет ASR самого YouTube. Скачивание
  аудио и Whisper (yt-dlp + модель) не включены, потому что это тяжело для бесплатного хостинга.
  В коде для них есть точка расширения (`YouTubeClient.transcript`).
- **Выборка отзывов.** Отзывы берутся из выборки Metacritic (до 7 на тональность, ведущая платформа)
  и при необходимости догружаются негативными. Это не весь корпус отзывов.
- **Userscore у свежих игр.** У игр, вышедших сегодня, Userscore часто ещё нет, и в интерфейсе стоит «—».
- **Стабильность порядка.** Порядок игр с одинаковой датой релиза в выдаче Metacritic нестабилен, а ответы
  кэшируются Cloudflare. Дедупликация идёт по id, поэтому повторов нет. Но если в течение дня в начало
  списка добавится много новых игр, страницы сдвинутся, и отдельные игры могут попасть в обработку
  только на следующий день.
- **Один процесс.** SQLite рассчитан на один процесс и одну реплику. Планировщик живёт внутри
  веб-процесса.
- **Сложность похожих игр.** Пересчёт идёт целиком, примерно O(n²) по играм с общими терминами. Для
  нескольких тысяч игр это секунды, для сотен тысяч понадобился бы ANN-индекс.
- **Неофициальный API.** У Metacritic нет публичного API. Используется тот же JSON-бэкенд, что и у их
  сайта, без ключа. Если он начнёт требовать `apiKey`, ключ можно брать из HTML `/game/` (описано
  в `docs/DATA_SOURCES.md`). Запасной вариант с разбором `__NUXT_DATA__` тоже описан там.
