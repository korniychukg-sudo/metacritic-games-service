# Безопасность и защита кнопки запуска

## Принудительный запуск

Кнопка на `/monitor` работает без логина, чтобы проверяющий мог ей пользоваться, но:

- одновременно идёт только один запуск (lock в процессе + lease в БД), повторный запрос получает 409;
- после окончания любого запуска действует пауза `MANUAL_RUN_COOLDOWN_SECONDS` (300 с): ответ 429
  с заголовком `Retry-After`, на кнопке и под ней идёт обратный отсчёт;
- не больше `MANUAL_RUNS_PER_DAY` (24) ручных запусков в сутки (плановые не считаются);
- `POST /run` и `POST /api/run` принимают только запросы с этого же сайта (`Sec-Fetch-Site`/`Origin`),
  кросс-доменный POST получает 403;
- если задан `RUN_TOKEN`, любой запуск не со страницы мониторинга требует `Authorization: Bearer <RUN_TOKEN>`
  (или заголовок `X-Run-Token`). Это касается `POST /api/run` и `POST /run` без `Sec-Fetch-Site: same-origin`
  (curl, скрипты). Кнопка в браузере продолжает работать без токена: браузер сам отправляет
  `Sec-Fetch-Site: same-origin`, а подделать этот заголовок со стороннего сайта нельзя. Старые браузеры
  без `Sec-Fetch-Site` при заданном токене получат отказ; по умолчанию токен не задан.

Главная защита от злоупотреблений: пауза и дневной лимит. Токен нужен, если сервис открыт в интернет
и вы не хотите, чтобы его запускали скриптами.

## Веб-страницы

- Шаблоны Jinja2 с автоэкранированием; ссылки из внешних данных проходят фильтр схем (только http/https),
  видео Metacritic только с `https://cdn.jwplayer.com`.
- Заголовки: `Content-Security-Policy` (без inline-скриптов и inline-стилей, `frame-ancestors 'none'`),
  `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`.
- Параметры `q` (до 200 символов), `platform` (до 100) валидируются; `page` в HTML-списке приводится к
  допустимому диапазону, в `/api/games` ограничен 1–10000.
- Ошибки на страницах показываются HTML-страницей без технических подробностей; в `/api/*` ответ JSON.
- В `/api/status` и `/api/runs` нет внутренних полей (имя хоста и pid процесса, держащего lease).
- Поток SSE `/api/events` закрывается через 10 минут (браузер переподключается сам), а uvicorn запускается
  с `--timeout-graceful-shutdown 5`, поэтому открытая страница мониторинга не мешает остановке контейнера.

## Контейнер

- Базовый образ закреплён по версии и digest: `python:3.12.15-slim-trixie@sha256:a6e34c59…`. Обновление:
  `docker buildx imagetools inspect python:3.12-slim` и замена строки `FROM`.
- Контейнер стартует от root только чтобы выдать права на `/data` (у примонтированного volume владелец root),
  при этом символические ссылки не обходятся и не меняются (`os.chown(..., follow_symlinks=False)`),
  и сразу понижает права до пользователя `app` (uid 10001).
- Один процесс и одна реплика: планировщик живёт в веб-процессе, SQLite рассчитан на один инстанс.

## Секреты и личные данные

- Сервис работает без секретов: LLM по умолчанию анонимная (Pollinations), Metacritic и YouTube без ключей.
  Если задать `LLM_API_KEY`, он уходит только в заголовок `Authorization` запроса к LLM и нигде не логируется.
- В `docs/samples/` публичные ключи фронтенда (`apiKey`, `INNERTUBE_API_KEY`), идентификаторы посетителя
  (`visitorData`, `visitor_data`, `datasyncId`, `rolloutToken`, `appInstallData`, `XSRF_TOKEN`) и IP-адрес
  клиента заменены на `REDACTED` и адрес из документационного диапазона 203.0.113.0/24.
